# Job Application Assistant

---

## Workflow

Когда пользователь предоставляет вакансию (URL или текст), следовать этому процессу:

### Step 1: Research & Evaluate Fit
- Загрузить текст вакансии (использовать WebFetch для URL). **403 - не тупик** - следовать порядку эскалации в `09-web-research.md`, прежде чем считать страницу недоступной, и предпочитать собственную публикацию работодателя листингу с агрегатора
- Сохранять **полный текст вакансии дословно** для архивации в Step 3b - никогда не сводку
- Проанализировать вакансию на требуемые компетенции, ключевые слова и приоритеты
- Исследовать компанию (сайт, LinkedIn, миссия, недавние новости) по `09-web-research.md`
- Оценить вакансию против профиля кандидата по фреймворку из `04-job-evaluation.md`
- Представить таблицу оценки и вердикт
- Предложить, стоит ли кандидату позвонить работодателю перед откликом (см. `04-job-evaluation.md`)
- Спросить пользователя, хочет ли он продолжить с заявкой

### Step 2: CV Recommendations (not a new CV file)
- Перед написанием любого из двух артефактов один раз вывести `<company>_<role>` по правилу **Subfolder naming** из `documents/README.md`; переиспользовать это же значение для файла рекомендаций, сопроводительного письма и пути архива Step 3b. Если правило говорит остановиться, потому что выведенное имя пустое, остановиться до создания любого файла.
- Прочитать три архетипных базовых резюме из Obsidian vault (`01-PROJECTS/поиск-работы/resumes/Орлов_Алексей_{РП,Agile,Dev}.md`) через `mcp__obsidian__vault_read`
- Выбрать наиболее подходящий архетип для этой вакансии (порядок приоритета и референс формулировок: archetype profile statements в `05-cv-templates.md`)
- Записать `documents/applications/<company>_<role>/cv-recommendations.md`: какое базовое резюме использовать, конкретное содержимое для добавления/переформулировки/перестановки приоритетов, честные пробелы — **никогда не переписанное резюме, никогда не изменение структуры разделов базового резюме**. То же содержимое попадает и в заметку Obsidian `applications/<company>_<role>.md` в Step 3b ниже — именно эту заметку, а не файл в этом репозитории, пользователь реально читает день за днём.

### Step 3: Write Cover Letter
- Следовать правилам стиля из `03-writing-style.md` (критично: без длинных тире, без клише) и политике честности из `applications/README.md` в Obsidian vault (не выпячивать пробелы по своей инициативе, никогда не искажать факт)
- Следовать структуре шаблона из `06-cover-letter-templates.md`
- Каноническая форма вывода - обычный текст в заметке Obsidian applications/ (Step 3b) — компилировать `cover_letters/cover_<company>_<role>.tex` в PDF только если вакансия/портал требуют файл-вложение (см. "PDF is optional" в `06-cover-letter-templates.md`)
- Убедиться, что письмо связывает конкретный опыт с требованиями роли
- Прогнать `humanizer-ru:humanize`, затем `humanizer-ru:audit` по тексту письма и прозе рекомендаций перед показом; залогировать оценку ЧИСТОТА в заметке Obsidian

### Step 3b: Record the Application
- Запускать этот шаг, когда оба документа уже существуют. CV или сопроводительное письмо, составленные по отдельности, - это ещё не заявка.
- Следовать **Step 6b команды `/apply`** (`.claude/commands/apply.md`) в точности: тот же заголовок, то же правило "сопоставить, затем обновить", та же строка `drafted`, тот же архив вакансии, тот же запрет трогать `job_scraper/seen_jobs.json`. Это описано там один раз, чтобы два пути не разошлись. Четыре значения названы собственными терминами `/apply`: `cv_file`/`cover_letter_file` - это пути, записанные в Steps 2 и 3 здесь, `source` - URL вакансии из Step 1, `deadline` - дедлайн заявки из текста вакансии, который Step 1 хранит дословно (пусто, если вакансия его не указывает - никогда не угадывать), а архив текста вакансии из пункта 7 - тот самый, что прочитал Step 1.
- **Также следовать Step 6c команды `/apply`** так же: записать заметку Obsidian `applications/<company>_<role>.md` и, если у вакансии есть соответствующая строка, заполнить колонки Оценка/Вердикт/Архетип в `Вакансии.md`. Та же причина, что и для Step 6b - одно определение, две точки входа, никогда не давать им разойтись.
- Этот шаг здесь есть, потому что Step 5 команды `/scrape` ведёт прямо в этот skill. Без него этот путь записывает два документа и не фиксирует ничего.

### Step 4: Interview Preparation
- Следовать фреймворку из `07-interview-prep.md`
- Подготовить ответы в формате STAR на вероятные вопросы
- Определить тезисы, специфичные для роли
- Составить вопросы, которые кандидату стоит задать интервьюеру

## Quick Commands

Пользователь также может попросить отдельные шаги без полного процесса:
- "Оцени эту вакансию" - только Step 1
- "Напиши CV-рекомендации для [компания]" - только Step 2
- "Напиши сопроводительное письмо для [роль] в [компания]" - только Step 3
- "Помоги подготовиться к интервью в [компания]" - только Step 4
- "Какие вакансии мне искать?" - обсуждение карьерной стратегии на основе профиля + фреймворка оценки
