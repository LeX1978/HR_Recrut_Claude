## Template: LaTeX moderncv (Banking Style)

Все резюме используют LaTeX-пакет moderncv со стилем "banking" и цветовой схемой "blue".

**Файл на выходе:** `cv/main_<company>_<role>.tex`
**Компилировать через:** **lualatex** на MiKTeX/TeX Live. pdflatex часто падает на современных установках MiKTeX с ошибками font-expansion в `fontawesome5`; lualatex обрабатывает те же исходники без проблем.
**Мастер-референс:** `cv/main_example.tex` (полное резюме со всеми компетенциями, опытом и достижениями - использовать как источник при сборке целевых резюме)

### Compile command

```bash
cd cv && lualatex -interaction=nonstopmode main_<company>_<role>.tex
```

Ожидаемый вывод: `Output written on main_<company>_<role>.pdf (2 pages, ...)`. Любое количество страниц, отличное от 2, - это ошибка, которую нужно исправить перед показом пользователю.

## Document Structure

```latex
\documentclass[11pt,a4paper,sans]{moderncv}
\moderncvstyle{banking}
\moderncvcolor{blue}

% Force the name and section headings to render in moderncv blue (color1).
% Default banking leaves them black: moderncvstylebanking.sty's \colorlet
% copies (not aliases) the pre-scheme accent colour, so the name colours are
% frozen before \moderncvcolor runs. Re-let them after. \namefont is the hook
% every name-style macro routes through, so this also works on moderncv 2.3.1
% (Debian/Ubuntu apt), which has no \firstnamestyle/\lastnamestyle at all.
\renewcommand*{\namefont}{\fontsize{34}{36}\bfseries\upshape}
\colorlet{firstnamecolor}{color1}
\colorlet{lastnamecolor}{color1}
\colorlet{namecolor}{color1}
\renewcommand*{\sectionstyle}[1]{{\sectionfont\color{color1}#1}}

\usepackage[utf8]{inputenc}
% pdflatex fallback only (the documented engine is lualatex, which skips this
% branch). Without T1 font encoding pdflatex builds accented letters with
% \accent, and the PDF text layer stores them decomposed - `e` + U+0300 rather
% than U+00E8 - so an ATS keyword match on "Genève" fails while the page looks
% right. moderncv 2.5 loads T1 itself under pdflatex; 2.3.1 (Debian/Ubuntu apt)
% does not. \ifpdftex comes from iftex, which every moderncv version loads.
\ifpdftex\usepackage[T1]{fontenc}\fi
% moderncv loads hyperref itself in an \AtEndPreamble hook, so \hypersetup
% must go in an \AtEndPreamble of our own: on moderncv < 2.4 a top-level
% \usepackage{hyperref} clashes with the class's own
% \RequirePackage[unicode]{hyperref}. From 2.4.0 the class passes its options
% through \PassOptionsToPackage instead, which is what removes that clash.
\AtEndPreamble{\hypersetup{
    colorlinks=true,
    linkcolor=blue,
    filecolor=magenta,
    urlcolor=blue,
    pdftitle={[YOUR_NAME] - CV},
    % Keep pdfpagemode=UseNone: this block runs after moderncv's own
    % \AtEndPreamble (moderncv.cls sets pdfpagemode there), so a FullScreen
    % value here would win and open every CV in fullscreen presentation mode.
    pdfpagemode=UseNone,
}}
\usepackage[scale=0.77]{geometry}
\usepackage{import}

% Personal data
\name{[FIRST_NAME]}{[LAST_NAME]}
% If you have no address to list, DELETE this whole line. \address{}{}{} fails
% with "There's no line here to end" on every moderncv version.
\address{[YOUR_ADDRESS]}{}{}
\phone[mobile]{[YOUR_PHONE]}
\email{[YOUR_EMAIL]}
\extrainfo{\href{[YOUR_LINKEDIN_URL]}{LinkedIn}, \href{[YOUR_GITHUB_URL]}{GitHub}}

\begin{document}
\makecvtitle

% 1. Profile statement (1-3 sentences, tailored per role)
% 2. Skills section
% 3. Education section
% 4. Professional Experience section
% 5. Selected Publications (if applicable)
% 6. Honors and Awards (if applicable)
% 7. References

\end{document}
```

### Color overrides

`\renewcommand*` для `\namefont` и три строки `\colorlet` в преамбуле обязательны на lualatex+MiKTeX. Без них имя и заголовки разделов рендерятся чёрным, даже если задано `\moderncvcolor{blue}`, что выглядит несогласованно с остальной синей акцентной схемой (ссылки, маркеры списков, иконки контактов). Причина: `moderncvstylebanking.sty` задаёт цвета имени через `\colorlet`, который *копирует* акцентный цвет таким, какой он есть до применения схемы, поэтому цвета имени замораживаются на значении до схемы; переприсвоение их через `\colorlet` после `\moderncvcolor{blue}` (как делает преамбула) заново закрепляет их на `color1`. `\namefont` - общий хук, через который проходит каждый макрос стиля имени, поэтому блок не зависит от версии - включая moderncv 2.3.1 из Debian/Ubuntu apt, где вообще нет `\firstnamestyle`/`\lastnamestyle`. Оба имени рендерятся жирным; если предпочитаете обычное начертание, замените `\bfseries` на `\mdseries` в строке `\namefont` (насыщенность теперь задаётся там, так что применяется ко всему имени). Не убирать эти override - на большинстве современных установок значения по умолчанию рендерятся заметно неправильно.

### Spacing inside itemize lists (important)

**Не ставить `\vspace{...}` между записями `\item` в списке `itemize`.** Хотя исходник выглядит симметрично, этот паттерн иногда даёт заметно увеличенный зазор перед одним из пунктов: `\vspace` между пунктами создаёт разрыв абзаца, который непредсказуемо взаимодействует с внутренним `\itemsep` списка, из-за чего LaTeX рендерит один из зазоров шире остальных. Убрать `\vspace` между пунктами и дать `itemize` использовать свой нативный равномерный интервал.

```latex
% WRONG - intermittently produces an oversized gap before one bullet
\begin{itemize}
\item \textbf{Foo}: ...
\vspace{1pt}
\item \textbf{Bar}: ...
\vspace{1pt}
\item \textbf{Baz}: ...
\end{itemize}

% RIGHT - uniform spacing using the list's native itemsep
\begin{itemize}
\item \textbf{Foo}: ...
\item \textbf{Bar}: ...
\item \textbf{Baz}: ...
\end{itemize}
```

Два похожих паттерна допустимы и должны сохраняться:
- `\vspace{1pt}` сразу после `\section{...}` (между заголовком раздела и первым пунктом) - это между заголовком и списком, а не между пунктами списка.
- `\vspace{3pt}` между блоками `\cventry` верхнего уровня в Professional Experience или Education - это даёт пространство между ролями и рендерится стабильно.

### Section headings must match the CV's language (important)

Заголовки разделов вроде `\section{Core Competencies}`, `Professional Experience`, `Education`, `Languages`, `Publications`, `Honors and Awards`, `References` (и любые другие, определённые в шаблоне), а также строка `Available upon request.` под References - всё это **буквальный английский текст, зашитый в шаблон** - сам себя он не переводит. Если язык резюме (см. `CV language` в профиле кандидата) не английский, переводить нужно и это всё, а не только текст в теле резюме - резюме с полностью локализованным profile statement и пунктами, лежащими под непереведёнными английскими заголовками разделов, выглядит небрежно и непоследовательно, и это легко забыть именно потому, что перевод прозы - очевидная, видимая часть работы. Разобранный пример для испанского: `Competencias Clave`, `Experiencia Profesional`, `Educaci\'on`, `Idiomas`, `Publicaciones`, `Distinciones y Premios`, `Referencias`, `Disponibles a solicitud.` То же правило применяется для любого другого целевого языка - проверять это явно на этапе верификации.

## Section-by-Section Tailoring

### Profile Statement / Elevator Pitch (Best Practice)
Это самый важный раздел для кастомизации. Он идёт сразу после `\makecvtitle`.

Написать 5-7 строк, работающих как "elevator pitch": сжатое, убедительное вступление, объясняющее, почему кандидат подходит именно *для этой конкретной роли*. Фокус на том, что работодатель получает от найма.

Когда роль лежит вне родного домена кандидата, **вести с аргумента переноса домена** - одно-два предложения, связывающие бэкграунд кандидата с проблемой работодателя (например, физика волн → обработка радарных сигналов), должны быть в начале profile statement, а не спрятаны в сопроводительном письме. Это самая сильная карта, которая есть у меняющего домен кандидата; разыграть её первой.

**Создать 2-3 шаблона profile statement под основные типы ролей:**

### Core Competencies / Skills Section (Best Practice)
Переставлять и расставлять акценты в зависимости от роли. Использовать жирные категории-метки.

Перечислить **5-7 ключевых компетенций** списком, адаптированным под конкретную вакансию. Для каждой компетенции коротко объяснить, какую ценность она добавляет для этой позиции.

Использовать собственный термин вакансии в жирной метке соответствующего пункта, когда это правдиво применимо - ATS и бегло читающие рекрутёры сопоставляют буквально, и "MLOps" в заголовке работает лучше, чем перефразировка вроде "ML Deployment".

### Education
- Всегда включать высшие степени
- Для senior-ролей держать образование кратким (только даты и названия)
- Включать темы диссертаций/дипломов, когда это релевантно целевой роли

#### In-progress qualifications must say so explicitly

**Просто диапазон лет недостаточен.** Запись вида `2025–2026`, увиденная в середине 2026 года, выглядит как *завершённая* степень, потому что читающий резюме бегло воспринимает закрытый диапазон как закрытый. Profile statement со словами "currently completing…" это не исправляет: именно запись в разделе Education - то место, где читающий проверяет квалификацию, поэтому она должна быть самодостаточной.

Указывать статус завершения прямо в самой записи:

```latex
\item{\cventry{2025--2026}{[Degree], [Field]}{[Institution]}{[Location]}{}{\vspace{1pt}
In progress, expected [Month Year]. [Relevant topics]
}}
```

Подходит любая последовательная форма: `In progress, expected <Month Year>.` / `Expected completion <Month Year>.` / поле даты `2025–present`.

Заявлять о квалификации, которой ещё нет, - это фактическая неточность, и она из тех, что обнаруживаются при проверке диплома или рекомендаций, а не на интервью. Предотвратить её ничего не стоит. То же касается незавершённых сертификаций и курсов.

**Проверять на согласованность:** для действующего студента profile statement, запись в Education и любая заметка о доступности/разрешении на работу должны давать одну и ту же дату завершения. Противоречие между ними хуже, чем любая отдельная версия.

### Professional Experience
- Переписывать пункты, подчёркивая аспекты, наиболее релевантные целевой роли
- Использовать 4-6 пунктов для самой недавней роли, 3-4 для предыдущей, 2-3 для более старых
- **Подчёркивать измеримые результаты**, где возможно: "Сократил время обработки на X%", "Модель принята командой в эксплуатацию"

#### Check tenure against visible output

Перед финализацией посмотреть на каждую роль так, как посмотрит незнакомый человек: **временной охват против того, сколько работы показано.** Двухлетняя роль, представленная одним проектом, читается как низкая продуктивность, справедливо это или нет. Читающий не может знать, чем было заполнено время, поэтому он додумывает - и додумывает не в пользу кандидата.

Сильнее всего это бьёт по **сменившим домен** (часть срока ушла на изучение новой области), по **работе с длинным циклом** (промышленное внедрение, клинические или регуляторные проекты, research - когда один этап действительно занимает кварталы) и по тем, кого работодатель держал на одном аккаунте или продукте.

Три честных способа исправить, по предпочтительности:

1. **Показать больше реальной работы.** Спросить, что ещё было в этот период. Часто есть реальные второстепенные проекты, внутренние инструменты или поддержка, которые не попали в резюме, потому что казались незначительными. Лучший вариант, когда материал есть.
2. **Явно выделить фазы внутри роли.** Если временной охват действительно состоял из этапов, сказать об этом прямо - начальный период изучения домена или поддержки команды, затем владение конкретной работой вплоть до её сдачи. Поэтапная дуга читается как кривая роста; недифференцированный многолетний блок - как застой.
3. **Назвать, что сделало цикл долгим.** Сбор данных из живой среды, валидация с экспертами домена, внедрение и итерации по реальному результату. Рецензенты, знающие домен, принимают это сразу.

**Никогда** не набивать выдуманными проектами и **никогда** не укорачивать даты трудоустройства, чтобы соотношение выглядело лучше. И то, и другое легко проверяется, и оба варианта хуже, чем проблема восприятия, которую пытались решить.

**Подготовить ответ и для интервью.** Если долгий срок при малой видимой продуктивности пережил все эти исправления, вопрос на интервью всё равно возникнет. Кандидату нужен готовый ответ из двух частей - чем реально было заполнено время и каким был результат - записанный в подготовку к интервью, а не придуманный на месте.

### Handling Employment Gaps (Best Practice)
Если в трудовой истории есть перерыв:
- Перерыв нужно объяснить по существу, если требуется
- Описать, как профессиональное развитие продолжалось во время перерыва
- Подать как осознанное развитие навыков и репозиционирование карьеры

### Publications
- Включить ссылку на Google Scholar, если применимо
- Выбрать 3-4 наиболее релевантные публикации (не всегда все)
- Для неакадемических ролей держать кратко

### Evidence Links
Везде, где резюме называет проверяемый артефакт - публичный проект, участие в хакатоне, публикацию - давать на него ссылку (`\href`), чтобы читающий мог проверить утверждение в один клик. Резюме, чьи самые сильные утверждения проверяемы, выглядит более убедительно и во всём остальном.

### Honors and Awards
- Держать формат кратким, одна строка на каждый пункт

### References
- Перечислить 2-4 рекомендателя с именем, должностью, компанией и контактом
- Закончить фразой: "Больше рекомендателей предоставляется по запросу."
- **Не прикладывать рекомендательные письма** - работодатели обычно связываются с рекомендателями напрямую

### LaTeX Special Characters (important)

Вакансии и данные профиля приходят как обычный текст; резюме - это LaTeX. Экранировать эти символы везде, где они попадают в текст - названия компаний, пункты достижений, списки навыков:

| Символ | Писать | Типичный триггер |
|---|---|---|
| `&` | `\&` | названия компаний: Bang \& Olufsen, Brüel \& Kjær, H\&M |
| `%` | `\%` | количественные достижения: "cut latency by 40\%" |
| `$` | `\$` | зарплата и суммы |
| `#` | `\#` | "ranked \#1", C\# |
| `_` | `\_` | имена файлов, идентификаторы кода |
| `~` | `\textasciitilde{}` | URL, тильды вроде "approx. 5 years" |
| `^` | `\textasciicircum{}` | строки версий, математика |

Два режима отказа заслуживают особого внимания:

- **`%` падает молча.** Неэкранированный `%` начинает LaTeX-комментарий: компиляция проходит без единой ошибки, а всё после `%` на этой строке исчезает из PDF. `Cut inference latency by 40% and saved DKK 2M annually` рендерится как "Cut inference latency by 40" - пункт сохраняет эффектно выглядящий фрагмент и теряет сам результат. Пункты с количественными достижениями - это ровно то место, куда толкает рекомендация ("использовать цифры, где возможно"), поэтому проверять каждый `%` в каждом пункте перед компиляцией.
- **`&` падает громко** внутри `\cventry` (ошибки выравнивания табуляции, `Missing } inserted`). Цикл компиляции это ловит, но лучше экранировать названия работодателей заранее, а не отлаживать компиляцию постфактум.

Смежная ловушка: пункт, текст которого начинается с буквального `[`, должен быть в фигурных скобках - `\item {[text]}` - иначе LaTeX распознает текст в квадратных скобках как опциональную метку `\item` и отрендерит её обрезанной за левым краем страницы при чистой компиляции без ошибок. Placeholder-пункты в примере резюме взяты в скобки именно по этой причине.

## Compile-and-Inspect Loop (MANDATORY)

После написания резюме и перед показом пользователю всегда компилировать и визуально проверять PDF. Итерировать, пока верстка не станет чистой. Порядок действий:

1. Запустить `lualatex -interaction=nonstopmode main_<company>_<role>.tex`
2. Проверить количество страниц на выходе: должно быть ровно 2
3. Прочитать PDF через инструмент Read и визуально проверить обе страницы
4. Проверить на **осиротевшие записи**: строка заголовка `\cventry` никогда не должна остаться одна внизу страницы 1, пока её пункты уходят на страницу 2

### Fixing common page-break problems

**Проблема: заголовок записи на странице 1, пункты осиротели на странице 2**
Добавить `\needspace{5\baselineskip}` сразу перед проблемным `\cventry`:
```latex
\needspace{5\baselineskip}
\item{\cventry{YEAR--YEAR}{Role Title}{Organization}{Location}{}{...}}
```
Подключить `\usepackage{needspace}` в преамбуле.

**Важно - использовать `\needspace` перед записями, никогда перед заголовками `\section`.** `\needspace` на уровне раздела переносит весь раздел (заголовок плюс содержимое) на следующую страницу, если запрошенное место не влезает, оставляя пустое пространство над ним и обычно *добавляя* страницу вместо экономии. Применять его только к конкретной `\cventry`, которая реально осиротела, и только после того, как компиляция это показала.

**Проблема: один хвостовой раздел уезжает на страницу 3 (например, References одиноко на странице 3)**
Добавить `\enlargethispage{2-3\baselineskip}` перед поздним разделом (например, перед `\section{Honors and Awards}`), чтобы растянуть страницу 2 на несколько строк. Это стандартный LaTeX-приём для спасения при небольшом переполнении.

**Проблема: 3 страницы со значительным содержимым на странице 3**
Резать содержимое - не сжимать geometry или `\vspace`. Правило см. в "Relevance-weighted cutting" ниже.

**Проблема: содержимое заканчивается рано на странице 2 (ощущается пустым)**
Вернуть ранее вырезанный пункт с самой высокой релевантностью - резюме, заканчивающееся в середине страницы 2, выглядит незаконченным.

## ATS Parseability

Большинство работодателей прогоняют резюме через ATS до того, как его увидит человек, а ATS читает встроенный в PDF **текстовый слой**, а не отрендеренную страницу. Резюме может пройти визуальную проверку и всё равно извлечься как мусор. После того как верстка прошла compile-and-inspect loop, проверить текстовый слой:

```bash
python tools/verify_pdf.py cv/main_<company>_<role>.pdf --dump-text cv/main_<company>_<role>.txt
```

Извлечение сначала пробует **pypdf** (`pip install pypdf`, лицензия BSD), затем Poppler `pdftotext`. Если фолбэк всё же использует `pdftotext -layout`, ему также нужен флаг `-enc UTF-8`: сборки на базе Xpdf по умолчанию используют Latin-1, из-за чего каждый не-ASCII символ в идеально нормальном резюме читается обратно как replacement-символ. Если ни один экстрактор недоступен, пропустить механическую проверку с предупреждением и полагаться на визуальное чтение PDF для проверки ключевых слов.

Что проверять при извлечении:

- **Контакты как буквальный текст.** Иконки контактов fontawesome из стандартного шаблона извлекаются как имена глифов (`MOBILE-ALT`, `Envelope`) - безобидный шум, поскольку сам адрес и номер напечатаны рядом. Проблемный сценарий - контактная деталь, которую несёт *только* иконка или гиперссылка (например, текст ссылки `LinkedIn`, чей URL не попадает в текстовый слой): невидимо для ATS. Адрес email всегда должен присутствовать как напечатанный текст.
- **Без искажённого вывода.** Маркеры `(cid:NNN)` или символы `�` означают, что шрифт встроен без Unicode-маппинга - ATS видит тот же мусор. Это встречается с необычными шрифтами в кастомных шаблонах, но не со стандартной настройкой moderncv под lualatex.
- **Порядок чтения.** Стандартный стиль banking - однoколоночный, поэтому порядок извлечения совпадает с визуальным порядком. Кастомные шаблоны (через `/add-template`) с боковыми панелями или многоколоночной версткой могут перемешивать несвязанные строки; если порядок извлечения нарушен, пользователь меняет совместимость с ATS на внешний вид, и его нужно об этом предупредить.
- **Покрытие ключевых слов.** Сопоставить обязательные/желательные термины вакансии с извлечённым текстом, на языке вакансии. Предпочитать точный термин вакансии синониму, когда это правдиво применимо - сопоставление в ATS часто буквальное. Никогда не добавлять ключевое слово, которое не подтверждается профилем. `verify_pdf.py --contains` сворачивает обе стороны по пробелам, Unicode-нормализации (NFC) и типографским заменам LaTeX перед сравнением - `'` попадает в текстовый слой как U+2019, а `--` как U+2013, поэтому `--contains "Master's degree"` и `--contains "2016-2024"` совпадают с тем, что шаблон реально рендерит. Выгруженный `.txt` никогда не сворачивается: это сырой слой, который видит ATS, поэтому проверка диапазона дат ниже читает именно дамп, а не `--contains`.
- **Диакритика на месте (pdflatex fallback).** Под pdflatex без кодировки шрифта T1 текстовый слой хранит буквы с диакритикой разложенными (`e` + комбинируемый гравис вместо `è`); pypdf читает это как `Gen` `eve` с лишним акцентом-пробелом, и ни та, ни другая форма не совпадает с введённым ключевым словом. Стандартный шаблон защищается от этого строкой `\ifpdftex\usepackage[T1]{fontenc}\fi`; сохранять эту строку в адаптированных резюме и кастомных шаблонах, которые могут компилироваться через pdflatex. Под lualatex это no-op.

### Date fields must be ASCII ranges (confirmed ATS import failure)

Об этом стоит знать, потому что отказ происходит **молча**. Резюме, прошедшее все остальные проверки в этом разделе - чистое извлечение, нет маркеров `(cid:)`, контакты на месте, правильный порядок чтения - всё равно может потерять даты при импорте. В реальном импорте резюме в Workday резюме, собранное из этого шаблона, потеряло дату окончания короткой контрактной роли и вообще не импортировало **ни одной** записи Education, что потребовало ручного ввода. С самим PDF или его текстовым слоем на вид всё было в порядке.

Две независимые причины, обе легко избежать:

1. **`--` в дате `\cventry` рендерится как среднее тире (U+2013), а не дефис.** LaTeX лигатурит `--` (два ASCII-дефиса, U+002D) в единый глиф среднего тире, поэтому `2016--2024` попадает в текстовый слой PDF как `2016<U+2013>2024`. Многие парсеры разбивают диапазоны дат только по ASCII-дефису и вообще не видят диапазон. Писать аргумент даты с **одним дефисом**:

   ```latex
   \item{\cventry{2016-2024}{Role Title}{Organization}{Location}{}{...}}   % парсится
   \item{\cventry{2016--2024}{Role Title}{Organization}{Location}{}{...}}  % среднее тире, может не распознаться
   ```

   Это касается **только аргумента даты**. Сохранять `--` везде, где он типографски корректен в тексте, например числовой диапазон вроде `EUR 600k--1M`.

2. **Одинокий год не даёт парсеру даты окончания.** Короткий контракт, мандат или стажировка, записанные как `\cventry{2016}`, импортируются как дата начала без ничего, что бы её закрывало. Использовать явный диапазон, с месяцами, если роль длилась меньше года:

   ```latex
   \item{\cventry{Mar 2016 - Jul 2016}{Contract Role}{Client}{Location}{}{...}}
   ```

   Там, где есть настоящий диапазон, использовать его, даже если один год был бы фактически верен - степень, записанная как `1995`, правдива, но импортируется хуже, чем `1992-1995`. Не выдумывать дату начала, которой нет; одинокий год выпуска - это нормально, просто стоит ожидать, что его придётся вводить вручную.

**Добавить это в проверки шага 5d**: после извлечения текстового слоя убедиться, что каждая запись опыта показывает начало *и* конец, разделённые ASCII-дефисом. Поскольку отказ молчаливый и невидим в PDF, иначе кандидат обнаруживает его только при заполнении формы заявки.

## Page Budget - Hard 2-Page Limit

Резюме **должно** уместиться ровно на 2 страницы после компиляции. Использовать эти лимиты содержания как ориентир:

| Раздел | Максимум |
|---------|-----------|
| Profile statement | 3-4 строки |
| Skills | 5 пунктов, по 1-2 строки |
| Самая недавняя роль | 4-5 пунктов |
| Предыдущая роль | 2-3 пункта |
| Более старые роли | 2 пункта (по 1 строке) |
| Education | 2-3 записи |
| Publications | 2-3 записи |
| Awards | 3 записи, по одной строке |
| References | "Available upon request." (одна строка) |

**В случае сомнений - резать, а не сжимать.** Уменьшение `\vspace` или масштаба geometry, чтобы силой втиснуть содержимое, делает резюме визуально тесным.

## Relevance-weighted cutting (the right way to shrink a CV)

**Резать по значимости, а не по разделам.** Статичные списки приоритетов ("сначала убрать самое старое образование, потом сократить самую раннюю роль...") ошибочны, когда релевантный пункт "низкого приоритета" конкурирует с нерелевантным пунктом "высокого приоритета". Пункт из старой роли, прямо отвечающий на вакансию, стоит больше, чем пункт из недавней роли, который на неё не отвечает.

Для каждой кандидатной строки оценить три вещи:

1. **Релевантность ИМЕННО ЭТОЙ вакансии** — упоминает ли строка названный инструмент, ключевое слово или заявленную обязанность из объявления?
2. **Уникальность** — это единственное место, где встречается это утверждение, или оно дублируется в другом месте резюме?
3. **Нарративная нагрузка** — зависит ли от неё сопроводительное письмо? Если удаление строки заставит переписать абзац сопроводительного письма, она несущая.

Резать строку с наименьшей суммарной оценкой первой, независимо от того, в каком разделе она находится.

### Practical order of cuts (easiest → last resort)

1. **Избыточность.** Если достижение фигурирует и в Core Competencies, и в пункте роли, версию в Core Competencies обычно проще убрать (пункт из опыта - более конкретное доказательство).
2. **Пустая формулировка в profile statement.** Предложение, которое просто повторяет то, что и так покажут Publications или Skills. ("Рецензируемые публикации по X..." уже есть как запись в Publications — profile может заявить это один раз и остановиться.)
3. **Малорелевантные пункты опыта.** Пункт о работе, не затрагивающей ключевые слова вакансии, независимо от того, где он находится. Это режется во всех разделах, прежде чем трогать структурный список.
4. **Малорелевантное вспомогательное содержимое.** Пункт из старой роли, не отвечающий целевой роли. Сертификация, не касающаяся стека вакансии. Запись о языке, которую можно сжать до одной строки.
5. **Малорелевантные публикации.** Оставить 1-2 публикации, лучше всего подходящие вакансии. Убрать остальные, прежде чем трогать пункты опыта.
6. **Структурные сокращения последней очереди.** Самая старая запись Education, сжатие старой роли до 2 пунктов, схлопывание Certifications в одну строку. Это происходит, только если сокращения по значимости выше уже исчерпаны.

### Pitfalls to avoid

- Не резать механически снизу статичного списка раздела без проверки релевантности. "Сначала убрать самую старую роль" — ошибка, если эта роль буквально про навык, который просит вакансия.
- Не резать единственный конкретный пример, на который опирается сопроводительное письмо. Релевантность измеряется в том числе против написанного сопроводительного письма, а не только против вакансии — интервьюеры прочитают оба документа.
- Не резать содержимое ради вписывания, если превышение пограничное (2.02 страницы). Предпочесть `\enlargethispage{2-3\baselineskip}` на позднем разделе для небольших превышений; сокращения содержимого оставить для настоящего переполнения (содержимое на странице 3, которое больше одного хвостового раздела).
