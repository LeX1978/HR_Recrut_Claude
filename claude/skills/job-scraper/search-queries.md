## Installed portal CLIs (primary for `/scrape`)

`/scrape` обнаруживает каждый portal-skill в `.agents/skills/*/SKILL.md` и сначала запускает его CLI. В комплекте: `hh-search` (РФ/СНГ, официальный `api.hh.ru`), плюс не привязанные к стране `linkedin-search` и `freehire-search`; любой skill, добавленный через `/add-portal`, подключается так же. Для запуска этих CLI **не нужна** соответствующая строка `site:` ниже.

Шаблоны запросов `site:` в этом файле - это **фолбэк на WebSearch** — для порталов без CLI, карьерных страниц компаний или когда CLI не сработал.

**Language scope:** писать каждую категорию запросов на каждом языке из таблицы Languages в CLAUDE.md (обычно 1-2, иногда больше). Вакансия, требующая незаявленный язык, как условие работы, исключается до оценки; вакансия, требующая более высокий уровень, чем заявлен, для языка, которым кандидат владеет, помечается флагом для собственного решения пользователя, а не исключается — см. Language Gate в `04-job-evaluation.md`, единственный источник истины для этого правила. Переводить ключевые слова каждой категории по смыслу, а не машинно слово-в-слово (например, "Frontend Developer" -> "Desarrollador Frontend", а не буквальный дословный перевод), если кандидат работает больше чем на одном языке.

## Query Categories

Queries are grouped by priority. Write **each category in every language from your Languages table** (see Language scope above). Combine each query with your location terms (e.g. your city, region, or metro area) where the site supports it.

**Organize by function, not job title.** The same underlying work carries different titles across companies and markets (a "Data Scientist" role at one employer may be posted as "Insights Analyst" or "Data Consultant" at another). Name each priority category after the function it covers, and list several plausible job titles as query variants within that category rather than betting an entire priority tier on one exact title string.

### Priority 1: Руководитель проекта с использованием ИИ / AI-augmented Delivery Manager

Главный приоритет (см. Target Sectors в CLAUDE.md) - роли, где практическое применение ИИ-инструментов в управлении проектом - явный плюс, не довесок. Покрывает и методологическую часть опыта в ПочтаТех (процессы, метрики, автоматизация отчётности).

**Ключевые слова по названию должности (уточнено пользователем 16-09-2026): стандартные названия должностей - "Руководитель проекта", "Руководитель ИТ-проекта", "Delivery Manager" - не "AI Project Manager".** Последнее - отдельный, редко встречающийся на этом рынке заголовок вакансии (в основном на международных площадках, часто означает управление ML/AI-инженерными проектами, а не практику ИИ-инструментов в самом PM), а не то, как реально называются целевые вакансии на hh.ru/habr. ИИ-уклон компании/вакансии проверяется по тексту описания и Quick Fit Assessment (Step 3 в `SKILL.md`), не по заголовку в поисковом запросе.

```
site:hh.ru "Руководитель проекта" Москва OR "Московская область" OR Санкт-Петербург OR удалённо
site:hh.ru "Руководитель ИТ-проекта" Москва OR "Московская область" OR Санкт-Петербург OR удалённо
site:hh.ru "Delivery Manager" Москва OR "Московская область" OR Санкт-Петербург OR удалённо
site:hh.ru "методолог" процессы разработки Москва OR Санкт-Петербург OR удалённо
site:career.habr.com "Project Manager" OR "Delivery Manager" OR "IT Project Manager"

```

## Location Filter

<!-- Сужено пользователем 16-09-2026: раньше "Москва и удалённо по РФ/СНГ - без ограничений"
(любая точка РФ/СНГ). Теперь домашний рынок ограничен тремя конкретными регионами + удалёнка;

**Домашний рынок (РФ/СНГ; hh.ru, geekjob.ru, career.habr.com, getmatch.ru, choicy.work):**
- Москва, Московская область, Санкт-Петербург - офис/гибрид/удалёнка, без ограничений.
- Удалённо по остальной РФ/СНГ - PASS (`schedule=remote`, без привязки к городу работодателя).
- Любая другая площадка/офис вне этих трёх регионов без пометки "удалённо" - EXCLUDE.
- Для `hh-search`: два отдельных вызова покрывают правило (см. `SKILL.md`'s Usage examples) -
  `-l moscow,moscow-oblast,spb` (любой график) и `-l russia --remote` (удалёнка по всей стране) -
  hh.ru применяет `area` и `schedule` через AND, не OR, одним вызовом оба случая не покрыть.

**Зарубежный трек (LinkedIn и другие международные площадки):**
- Только удалённые вакансии (`Remote`) - активный поиск очного/гибридного переезда за рубеж
  сейчас не ведётся.
- Только вакансии, где рабочий язык - английский (см. Language Filter ниже) - не испанский/
  другой локальный язык, даже если компания расположена в целевой стране релокации.
- Открытость к самой релокации (Испания, Филиппины, страны Европы) остаётся личным
  предпочтением кандидата (`CLAUDE.md`'s Deal-breakers, `04-job-evaluation.md`'s Location gate) -
  это про то, что кандидат бы принял, если предложат, не про то, что сейчас активно ищется.

## Language Filter

Рабочие языки и уровни кандидата - в таблице Languages в CLAUDE.md. При фильтрации результатов скрапинга применять Language Gate из `04-job-evaluation.md`: вакансия, требующая вообще незаявленный язык, исключается; вакансия, требующая более высокий уровень, чем заявлен, для языка, которым кандидат владеет, не исключается, а явно помечается флагом (см. Step 3 "Quick Fit Assessment" в `job-scraper/SKILL.md` о том, как этот флаг отображается в выводе `/scrape`). Вакансии, просто *написанные* на языке, которым кандидат не владеет, но не требующие его по работе, - это нормально.

**Только для зарубежного трека (решение 16-09-2026):** дополнительно ограничивать вакансиями, чей рабочий язык - английский - исключать зарубежную вакансию, требующую незнакомый кандидату язык как рабочий (например, только испанский), даже там, где общий Language Gate выше только пометил бы флагом, а не исключил. На домашний трек РФ/СНГ это не распространяется.

## Date Filter

Включать только вакансии, опубликованные за последние 14 дней, или с дедлайном подачи, который ещё не прошёл. Если дату публикации определить не удаётся, включить вакансию, но пометить как "дата неизвестна".

## Adapting Queries

Если пользователь указывает фокус-область, выбрать запросы из соответствующей категории и дополнительно сгенерировать 2-3 кастомных запроса под этот фокус. Например:
- "/scrape [фокус-область]" -> релевантные запросы категории + кастомные запросы под конкретный фокус
