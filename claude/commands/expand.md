# /expand - Competency Expansion from Documents and Online Presence

Обогащение профиля кандидата за счёт компетенций, скрытых в документах и публичном онлайн-присутствии. Эта команда только аддитивна — она никогда не меняет существующее содержимое профиля, только расширяет его.

Шаги — **строго по порядку**, ничего не пропускать.

---

## Step 0: Read Existing Profile Files

Прочитать эти два файла параллельно, прежде чем что-либо делать. Нужно знать, что уже есть, чтобы не предлагать дубликаты.

- `.claude/skills/job-application-assistant/01-candidate-profile.md`
- `.claude/skills/job-application-assistant/02-behavioral-profile.md`

Держать это содержимое в контексте на протяжении всей команды. Не перечитывать эти файлы позже.

## Step 1: Discovery — Scan All Sources

Просканировать каждый доступный источник на «единицы опыта» — всё, что подразумевает навык, знание или компетенцию. Обрабатывать источники в этом порядке.

### 1a. documents/cv/
Прочитать все файлы в `documents/cv/`. Извлечь:
- Каждый перечисленный курс или модуль (включая университетские курсы и онлайн-курсы)
- Каждый упомянутый сертификат, с издателем и датой
- Каждый буллет обязанностей на работе (инструменты, методы, результаты)
- Каждый независимый или сторонний проект
- Каждую волонтёрскую или внеучебную роль

### 1b. documents/linkedin/
Прочитать все файлы в `documents/linkedin/`. Извлечь:
- Курсы и сертификаты из раздела «Licenses & Certifications»
- Список навыков и рекомендаций от коллег
- Волонтёрский опыт
- Раздел Projects
- Любые специфичные для платформы пункты, ещё не найденные в резюме

### 1c. documents/diplomas/
Прочитать все файлы в `documents/diplomas/`. Извлечь:
- Все названия курсов/модулей из зачётки
- Тему и область диплома
- Название специализации или трека, если есть

### 1d. documents/references/
Прочитать все файлы в `documents/references/`. Извлечь:
- Лексику компетенций, которую использует рекомендатель (какие навыки или качества упоминает)
- Любые конкретные проекты, инструменты или методы, названные в тексте

### 1e. GitHub Profile
Найти имя пользователя GitHub в `01-candidate-profile.md`. Если URL или имя пользователя GitHub есть:

1. Через WebFetch или WebSearch получить публичный профиль и закреплённые репозитории
2. По каждому найденному репозиторию:
   - Получить README репозитория
   - Отметить: название, описание, основной язык(и), топики/теги, любые фреймворки или библиотеки, упомянутые в README
   - Если репозиторий представляет независимый технический проект (не пустая заготовка и не некастомизированный форк) — извлечь сводку проекта (предметная область, технологический стек, демонстрируемые технические результаты) для рассмотрения в Independent Projects
3. Также получить полный список репозиториев, если доступен (чтобы поймать незакреплённые репо)

Если имени пользователя или URL GitHub в профиле нет — пропустить этот источник и отметить, что пропущен.

### 1f. Other URLs in Profile
Проверить `01-candidate-profile.md` на другие URL (сайт-портфолио, личный сайт, Kaggle, Google Scholar, ResearchGate, ссылки на публикации). По каждому:
- Получить страницу
- Извлечь любые инструменты, методы, датасеты, награды или навыки, упомянутые там

## Step 2: Web Enrichment

По каждой единице опыта, найденной на Step 1, поискать в вебе, чтобы извлечь подразумеваемые ею компетенции. Применять оба подхода ниже — не выбирать один вместо другого.

### Approach A: Direct lookup (explicit tools and frameworks)
Если пункт называет конкретный инструмент, фреймворк, библиотеку, метод или платформу — искать напрямую:
- `"[название курса] [провайдер] syllabus learning outcomes"`
- `"[название сертификата] skills covered exam guide"`
- `"[название инструмента/фреймворка] skills what you learn"`

Получить самую релевантную страницу и извлечь список компетенций.

### Approach B: Inferred competencies (from description and context)
По каждому пункту, независимо от того, нашёл ли что-то Approach A, также рассуждать по описанию:
- Какую предметную область затрагивает этот пункт?
- Какие методы, навыки или знания нужны, чтобы делать эту работу?
- Какой стандартный toolchain для такой работы?

Объединить оба подхода в единый список компетенций по каждому пункту.

### Prioritise web lookup for:
- Названные онлайн-курсы (Coursera, edX, Udemy, LinkedIn Learning, DataCamp, fast.ai и т.п.)
- Названные сертификаты (AWS, GCP, Azure, Databricks, Tableau и т.п.)
- Университетские курсы со стандартной программой
- Репозитории GitHub с README, называющим конкретные технологии

### Infer (without web lookup) for:
- Общие буллеты обязанностей без названного инструмента
- Расплывчатые описания проектов
- Формулировки из рекомендательных писем (уже сформулированы как компетенция — просто зафиксировать)

## Step 3: Build Competency Map

После обогащения всех пунктов собрать дедуплицированную карту компетенций. Сгруппировать находки по категориям:

**Technical Skills — Primary** (основные языки, фреймворки, методы, используемые регулярно)
**Technical Skills — Secondary** (инструменты, с которыми был опыт, но не основные)
**Domain Knowledge** (экспертиза в предметной области: геофизика, ML, NLP и т.п.)
**Methods and Practices** (agile, контроль версий, воспроизводимость, тестирование и т.п.)
**Soft / Behavioral** (сигналы лидерства, коммуникации, совместной работы из рекомендаций и описаний проектов)
**Independent Projects & Portfolio** (отдельные технические проекты с GitHub с предметной областью, стеком и ключевой технической вехой)

По каждой компетенции зафиксировать:
- Название компетенции
- Исходный пункт, из которого она взята (например, «Coursera — Deep Learning Specialisation», «GitHub — repo-name», «Рекомендательное письмо — Йенс Йенсен»)
- Пришла ли она из прямого поиска (A), вывода (B), или обоих

По каждому проекту зафиксировать:
- Название проекта
- Однострочную сводку: решённая проблема, использованный стек и проверяемый результат/влияние
- Источник (например, «GitHub — repo-name»)

Убрать всё, что уже есть в `01-candidate-profile.md` или `02-behavioral-profile.md`.

## Step 4: Present Grouped Summary

Показать все новые компетенции и предложения по проектам на review пользователю, прежде чем что-либо записывать. Формат:

```
## /expand found [N] new competency signals across [M] sources

**COURSES & CERTIFICATIONS**
Source: [название курса/сертификата — провайдер]
  + [Компетенция 1]
  + [Компетенция 2]
  ...

**PROJECTS & PORTFOLIO**
Source: [GitHub — repo-name]
  + [Название проекта]: [проблема, стек, результат]
  ...

**GITHUB — [repo-name]**
Source: README + вывод из стека технологий
  + [Компетенция 1]
  + [Компетенция 2]
  ...

**JOB RESPONSIBILITIES — [Компания, Роль]**
Source: буллеты резюме + прямой поиск по инструменту
  + [Компетенция 1]
  ...

**BEHAVIORAL SIGNALS**
Source: [Рекомендательное письмо — Имя / LinkedIn About / лидерство в проекте]
  + [Сигнал 1]
  ...

[дальше разделы по необходимости]
```

Затем спросить:

> **Как продолжить?**
>
> - **`all`** — добавить всё выше в профиль
> - **`review`** — пройти по каждой группе источников по одной
> - **`skip`** — отменить, ничего не записывая
>
> Или перечислить конкретные группы для пропуска (например, «пропустить GitHub, добавить остальное»).

Дождаться ответа пользователя, прежде чем что-либо записывать.

## Step 5: Write Confirmed Additions

Применить только подтверждённые пункты. Использовать Edit, чтобы дописать в релевантные разделы каждого файла — не переписывать файлы целиком.

### Additions to `01-candidate-profile.md`
- Независимые проекты → дописать в раздел `## Independent Projects` в формате `- **[Название проекта]**: [Описание со стеком и результатом] *(GitHub — repo-name)*`
- Технические навыки (основные и вторичные) → дописать в раздел Technical Skills
- Экспертиза в предметной области → дописать в раздел Domain Knowledge или Technical Skills (по существующей структуре)
- Методы и практики → дописать соответственно

По каждому дополнению добавить короткую пометку источника в комментарии или скобках: *(Coursera — Deep Learning Specialisation)*, *(GitHub — project-name)* и т.п. Это делает будущие прогоны `/expand` идемпотентными.

### Additions to `02-behavioral-profile.md`
- Поведенческие/soft-сигналы → дописать в раздел «Strongest Behavioral Traits» или «How I Work Best» (по существующей структуре)
- Всегда помечать выведенные поведенческие дополнения: *[Выведено из рекомендательного письма — Имя / проверить перед тем, как полагаться на это]*

## Design Principles

- **Additive only.** Эта команда никогда не меняет существующее содержимое профиля. Только дописывает.
- **Source-traceable.** Каждое дополнение фиксирует, откуда оно взято, так что будущие прогоны идемпотентны, а пользователь может позже проверить или убрать отдельные пункты.
- **Both approaches, always.** Веб-поиск и вывод применяются вместе — не как альтернативы. Названный курс получает и официальную программу, И обоснованный список компетенций.
- **User confirms before writing.** Полная карта компетенций показывается и подтверждается, прежде чем тронут хоть один файл.
- **Behavioral signals are labeled.** Всё, выведенное из тона, формулировок или косвенных сигналов, помечается как выведенное, чтобы это критически проверили.
- **GitHub is fully scanned.** Проверяются все публичные репозитории, не только закреплённые — незакреплённые репо часто содержат значимые сигналы компетенций.
- **Portfolio & projects grounded in code.** Независимые проекты, добавляемые в профиль, должны отражать реальные проекты, найденные в публичных репозиториях GitHub — никогда не выдуманные утверждения о проектах.
